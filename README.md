# 四川麻将 · 血战到底

[![CI](https://github.com/gangzhao2021/Mahjong/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/gangzhao2021/Mahjong/actions/workflows/ci.yml)

1 名真人 + 3 个 AI 的休闲麻将手游。需求见 [PRD](Mahjong%20Mobile%20Game%20V1%20PRD%20and%20Development%20Prompt.md)。

当前进度：**第 1–6 阶段全部完成**（核心原型、AI 性格与对话、账号与经济系统、AI 长期记忆、管理后台、上线前打磨），另有牌局重启恢复和英文界面。

## 目录结构

```
packages/engine     规则引擎（纯函数、可设种子、按座位视图），PRD 附录 A
packages/ai-play    对局 AI：向听数 + 进张 + 防守 + 牌型价值，三档技术水平；只给出抽象的手牌评估
packages/dialogue   对话引擎：触发事件、诈唬意图、模板台词、提示词、谁来说话、内容审核
packages/protocol   客户端与服务端之间的 WebSocket 消息类型
apps/server         权威服务端：房间、计时器、托管、断线重连、操作日志、牌桌聊天、大模型接入
apps/server/config  AI 角色与对话、经济参数（金币、场次、每日奖励）、国内合规参数；第 5 阶段移到管理后台
apps/mobile         Expo (React Native) 横屏客户端，也可在浏览器里运行
apps/admin          管理后台（React + Vite），构建后由服务端在 /admin 提供
```

## 运行

需要 Node 22+ 和 pnpm 10+。

```bash
pnpm install
```

启动服务端（HTTP 与 WebSocket 都在 http://localhost:8787，WebSocket 路径为 `/ws`）。默认使用内置的 PGlite 数据库，数据存在 `apps/server/data/`，无需安装 PostgreSQL：

```bash
pnpm server
```

在浏览器里运行客户端（最快的试玩方式）：

```bash
pnpm mobile:web
```

在手机或模拟器上运行：先执行 `pnpm mobile`，然后用 Expo Go 扫码。真机需要把服务器地址指向电脑的局域网 IP，例如 `EXPO_PUBLIC_SERVER_URL=http://192.168.1.20:8787`。Google 和微信登录需要开发版（development build），Expo Go 里只能用游客、手机号和 Apple（iOS）。

国内版本地调试：用 `REGION=china DATA_DIR=data-china` 启动服务端。短信验证码会打印在服务端日志里（`[dev SMS]`），实名认证用的是开发用校验器（只校验身份证号格式）。

### 管理后台

1. 生成管理员账号（密码至少 12 位），把输出的三行写进 `apps/server/.env`（已被 git 忽略，服务端启动时自动读取）：

```bash
pnpm admin:setup 你的用户名 你的密码
```

2. 把输出里的 `otpauth://` 链接（或其中的 secret）添加到身份验证器 App（Google Authenticator、1Password 等）。
3. 构建后台，然后访问 http://localhost:8787/admin/ ：

```bash
pnpm admin:build
```

开发后台界面时可用 `pnpm admin:dev`（http://localhost:5174/admin/，接口自动转发到 8787）。

### 服务端环境变量

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | 生产环境的 PostgreSQL 连接串；不设则使用 PGlite |
| `SESSION_SECRET` | 会话签名密钥（≥32 字符）。不设时开发环境自动生成并保存在数据目录 |
| `ID_HASH_SECRET` | 手机号与身份证号哈希用的密钥，生产必须设置 |
| `APPLE_CLIENT_IDS` | Apple 登录的 bundle ID（逗号分隔） |
| `APPLE_TEAM_ID`、`APPLE_KEY_ID`、`APPLE_PRIVATE_KEY` | 注销账号时撤销 Apple 授权所需（App Store 要求） |
| `GOOGLE_CLIENT_IDS` | Google 登录的客户端 ID（逗号分隔） |
| `WECHAT_APP_ID`、`WECHAT_APP_SECRET` | 微信登录（国内版） |
| `ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH`、`ADMIN_TOTP_SECRET` | 管理员账号（用 `pnpm admin:setup` 生成）；不设则后台关闭 |
| `ADMIN_IP_ALLOWLIST` | 允许访问后台的 IP（逗号分隔，可选） |
| `TRUST_PROXY=1` | 部署在反向代理后面时设置，后台 IP 白名单才能拿到真实 IP |

客户端：`EXPO_PUBLIC_SERVER_URL`，以及 Google 登录用的 `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`、`EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`、`EXPO_PUBLIC_GOOGLE_IOS_URL_SCHEME`。

### AI 对话用的大模型

不配置也能玩：AI 会用模板台词和表情。要让 AI 用大模型说话，启动服务端前设置环境变量：

| 变量 | 说明 |
|---|---|
| `ANTHROPIC_API_KEY` | 海外版用 Claude（默认）。日常反应用 `claude-haiku-4-5`，高价值时刻（大牌、回复玩家）用 `claude-opus-5-5`，可在 `config/dialogue.json` 里改 |
| `REGION` | `global`（默认）或 `china`。国内版默认温和语气，并压低嘲讽强度 |
| `LLM_PROVIDER` | `anthropic` / `openai-compatible` / `none`，不设时按地区选 |
| `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_ROUTINE`、`LLM_MODEL_HIGH` | 国内版用的已备案模型（默认通义千问 DashScope 兼容接口） |

配好密钥后，用下面的命令检查真实模型是否工作正常（会产生几次真实调用）：

```bash
pnpm llm:smoke
```

它会用中文和英文（国内版只用中文）各发几条真实请求：普通反应、大牌（高价值模型）、带注入攻击的玩家聊天，再加一次记忆总结。每条回复都按服务端的标准检查：格式、长度、内容审核、语言对不对，以及有没有泄露系统提示词。全部通过时退出码为 0。

## 第 1 阶段已实现

- 血战到底完整规则：换三张、定缺、碰、直杠/补杠/暗杠、一炮多响、过手胡、抢杠胡、杠上花、杠上炮、呼叫转移、海底捞月、天胡/地胡、查花猪、查大叫、退税、番型表与封顶。所有可变规则都在 `RuleSet` 里。
- 服务端说了算：客户端只收到自己座位的视图。AI 也只看自己的视图，从结构上就没法作弊。
- 每个决定都有计时；连续 2 次超时自动托管；断线或切到后台也转为托管；胡牌后可跳过直接看结算；中途离开照常结算。
- 每手牌都保存为 `{种子, 规则, 操作列表}`，能用 `replayHand` 原样重放。
- 客户端：横屏牌桌、双击或上滑出牌、换三张选牌、定缺建议、碰/杠/胡/过按钮、倒计时、托管提示条、结算面板（含结算明细）。

## 第 2 阶段已实现

- 10 种性格、25 个固定 AI 角色（名字、头像、性格固定，技术水平每局随机），按权重抽取。
- 对局事件触发对话：碰、杠、点炮、大牌、抢杠、危险牌、花猪、开局、冷场等；AI 之间也会互相接话。
- 诈唬：对局 AI 只给出抽象意图（例如假装快听了），大模型拿不到任何具体的牌；测试里检查了提示词中不含任何牌名。
- 对话完全异步，不阻塞出牌；过时的台词直接丢弃；按人数、冷却时间和每局次数控制成本。没有大模型或超出预算时，自动改用模板台词。
- 玩家可以自由打字（可以 @ 某个 AI）、发快捷语和表情。消息先审核再发出，有限流，多次违规会暂停聊天；玩家输入在提示词里只作为数据，AI 不会照着执行。
- 嘴碎程度可在大厅或聊天面板里设为温和、毒舌或安静，设置会记住；安静模式完全不调用大模型。
- AI 座位都有 "AI" 标识，并显示性格。

## 第 3 阶段已实现

- 账号：游客、Apple、Google（海外版）；手机号验证码、微信、Apple（国内版）。服务端校验所有第三方凭证；会话令牌存在系统钥匙串里。
- 游客可绑定其他登录方式，原账号原样升级；若该登录方式已属于另一个账号，不合并，可退出后用它登录。
- 账号注销：删除资料和钱包，撤销 Apple 授权，金币流水保留但匿名化。
- 金币：新玩家 20,000；每手牌结算后入账，余额永远不会为负；每笔变动写入不可修改的流水，重复结算不会重复记账。
- 场次：练习场（不结算）、初级、中级、高级，各有准入金币。私人房免费创建，底分不超过余额的 1%，可改局数和部分规则，带房号。
- 每日奖励：5 天循环，错过不清零，领完重新开始；每天 04:00（UTC+8）刷新。
- 离开后由托管打完的牌局，结果会在下次登录时显示。
- 国内版：非游客必须实名；未成年人只能在规定时段游戏，时间到会提前提醒并自动托管打完；游客每台设备每 15 天试玩 1 小时。
- 客户端：登录页、实名认证、大厅（金币、每日奖励、场次、私人房）、账号页（昵称、头像、嘴碎程度、绑定、金币记录、退出、注销），牌局内显示场次和金币变化。

## 第 4 阶段已实现

- 每个 AI 角色对每个玩家单独记一份关系：一起打过几场、谁点过谁的炮、谁赢过谁、对手程度、记仇（附录 B）。对手程度和仇恨会随时间淡化。
- 值得记住的事：点炮、被胡大牌、被抢杠、花猪、玩家说过的话；按重要程度打分，每个角色最多保留 50 条，玩家的话最多 10 条。
- 玩家画像：根据统计（点炮率、胜率、自摸、大牌、聊天多少）概括打法和习惯，所有角色共用。
- 写入：每手牌结束时直接更新计数和事件，不调用大模型；每场结束时调用一次大模型润色本场的记忆措辞和玩家画像，结果先审核再保存；没有大模型就保留模板措辞。
- 读取：开局时，和你最有渊源的角色先打招呼（"又是你？上次那把我可还记着呢"）；你再点同一个人的炮，对方会翻旧账。用大模型时，每次只带 2–3 条最相关的记忆，并避免反复提同一件事。
- 隐私：记忆可按玩家、按（角色、玩家）、按角色查看、重置和删除；注销账号会一并删除。管理接口在第 5 阶段接入后台。

## 第 5 阶段已实现

- 管理员：单一账号，密码只存 scrypt 哈希，必须加身份验证器动态码（同一个码不能用两次），连续失败 5 次锁 15 分钟，可选 IP 白名单，8 小时无操作自动退出；后台的每个操作都写进操作日志。
- 玩家管理：搜索、按状态和登录方式筛选、排序；详情里看金币记录、AI 记忆（可按角色或全部清除）。
- 金币调整：必须填原因，记录调整前余额、调整额、调整后余额、原因和时间；扣除超过余额时只扣到 0。
- 封禁：1 天、7 天、自定义小时、永久，原因可不填且玩家看不到；封禁时立即踢下线并结束当前牌局；可解封。
- 数据概览：日活、新注册、金币发放与消耗（私人房单独统计）、平均在线时长，支持最近 7 天、30 天和自定义区间，带趋势图和表格视图。
- 配置（立即对新牌局生效，存在数据库里，JSON 文件只作初始值）：经济参数（新手金币、每日奖励循环、刷新时间、场次、私人房上限）、AI 对话参数、技术水平权重、大模型和每日上限、快捷语、聊天限制。
- 性格与角色：新建、编辑、停用、删除，设置权重并显示换算后的出现概率；删除角色会删除它的全部记忆；系统保证至少有 3 个可用角色。名字库和头像库用于新建角色。
- 内容审核：被拦截的玩家消息、玩家举报的 AI 台词（客户端聊天记录里每条 AI 台词都可举报），可标记已处理。

## 第 6 阶段已实现

- 新手教程：6 节小课（出牌、换三张与定缺、碰杠、胡牌与番数、自摸与流局、牌桌功能），在真实牌桌界面上一步步跟着做，打错会提示；不联网、不登录也能学，进度保存在本机。
- 声音：摸牌、出牌、碰、杠、胡、按钮、AI 说话的音效，大厅和牌桌的背景音乐；音效和音乐可以分别开关；不会打断玩家自己在听的音乐，静音开关打开时不出声。
- 动画：出的牌、碰杠胡提示和对话气泡有弹出动画；系统开了“减少动态效果”时不播放。
- 出错处理：界面崩溃时显示“出了点问题”页面，可重新加载；未捕获的错误自动上报到服务端（同一个错误一分钟只报一次，每个 IP 每分钟最多 20 条），后台新增“崩溃报告”页，按错误分组显示次数、玩家数、平台、版本和堆栈。服务端记录未处理的异常。
- 重连：App 回到前台时立即重连，不再等待退避时间；收到格式错误的消息不会让牌桌崩溃。
- 性能：AI 决策平均约 0.7 毫秒，一局约 50 毫秒，有基准测试防止性能退化。
- 上架准备：首次启动先显示隐私同意（同意前不登录、不生成设备标识；不同意也能学教程）；服务端提供隐私政策、用户协议和第三方 SDK 清单页面（草案，需法务审核）；登录页有协议链接，中国版登录页有健康游戏忠告和适龄提示；账号页新增“关于”（版本、AI 说明、金币说明、备案号）；`eas.json` 里有开发、预览、正式和中国正式版的打包配置；iOS 隐私清单和加密声明已填。上架前要人工完成的事项见 [docs/release-checklist.md](docs/release-checklist.md)。

## 第 6 阶段之后的补充

- 服务端重启不丢牌局：进行中的牌局每次变化后（合并为最多每 250 毫秒一次）存进数据库，启动时恢复。恢复的牌局先等玩家回来（默认 60 秒），玩家重连后接着打；等不到就由系统托管打完，结果在玩家下次登录时显示。重启前已结束但还没结算的那一局会补结算（结算本身是幂等的，不会重复扣加金币）。正常关停时会先写入最新状态；进程被直接杀掉时，最多丢失最后 250 毫秒内的操作。
- 英文界面：按手机系统语言自动选择中文或英文，可在登录页和“账号”里切换（国内版固定中文）。界面文字、新手教程、牌面、番型和结算名称、隐私政策和用户协议都有英文版。英文玩家的牌桌上，AI 角色用英文名字，模板台词、快捷语、表情名称都是英文，大模型也会被要求用英文说话；新账号的默认昵称是 “Player” 加编号。后台可以给角色和性格填英文名。
- 真实大模型检查：新增 `pnpm llm:smoke`（见上文“AI 对话用的大模型”）。

## 上线准备

- 部署：服务端和管理后台打包成 Docker 镜像，`docker-compose.yml` 带 PostgreSQL，环境变量模板在 `.env.example`。生产环境缺少会话和哈希密钥时拒绝启动。步骤、HTTPS、备份和容量见 [docs/deploy.md](docs/deploy.md)。
- 容量：压测脚本 `pnpm --filter @mahjong/server loadtest`。单进程约 1,000 桌同时在打时平稳（/health p99 约 40 毫秒、内存约 500 MB），2,000 桌时单核跑满。没人看着的牌局（离开、断线、重启恢复）共用每秒 400 步的预算，不会挤占正在打的桌子；压测中发现并修复了大量弃局同时快进导致的内存耗尽。
- 登录和聊天日志（附录 D.6）：记录每次登录（方式、IP）和牌桌上的每句话（玩家聊天、快捷语、表情、AI 台词）。后台玩家详情里可以查看，每次查看记入操作日志。每 6 小时自动清理过期数据：聊天和登录记录默认 90 天（国内版至少 180 天），崩溃报告 90 天，牌局回放 180 天。国内版玩家注销后这些记录保留到期满再删。
- 登录限流：同一 IP 每 10 分钟最多 30 次登录请求（`AUTH_RATE_LIMIT` 可调），防止脚本批量注册刷新手金币。
- 真机测试：步骤和测试清单见 [docs/device-testing.md](docs/device-testing.md)。
- 应用图标换成了程序绘制的占位图（绿色桌布上的一张五筒，`apps/mobile/scripts/generate-icons.py`）。

## 已知限制（按 PRD 留到后续阶段）

- 微信登录需要接入微信开放平台 SDK 并打包开发版；当前客户端里显示为暂不支持。短信发送和实名认证只有开发实现，正式上线需接入短信服务商和国家实名认证系统（附录 D）。

- 内容审核目前只有本地词库加联系方式和链接过滤；第三方审核服务（附录 D.5）待选型后接入。
- 本机没有 Claude 凭证，所以真实的大模型调用还没有跑过；配好密钥后运行 `pnpm llm:smoke` 即可验证。
- 一台服务端进程管理所有牌局；多实例部署需要按玩家分配到固定实例（牌局检查点按玩家存储，换实例后可以恢复）。
- 性格的专属模板台词只有中文，英文牌桌用通用英文模板；AI 记忆的摘要也是中文（只给大模型看，不展示给玩家）。
- 音效、音乐和应用图标都是程序生成的占位素材，上架前要换成正式设计。
- 还没在 iOS 和 Android 真机上跑过（见 docs/device-testing.md）。
- `app.json` 里的 bundle ID `com.example.mahjong` 和 `eas.json` 里的服务器地址是占位，上架前要改。
